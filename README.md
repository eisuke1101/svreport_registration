# SVレポート登録

SVレポート（`SVレポート_2026.10ver.xls`）の入力フォーム。HTML（GAS HtmlService）＋ Google Apps Script。

- 校舎・実施日を選ぶと、前回・前々回の結果（倍率適用後の減点・点数）を表示
- 連続指摘（2回目×2／3回目×3／4回目以降×4、レベル違いも連続、年度またぎも連続、未実施回は飛ばして直近を参照）を自動計算
- 登録すると、テンプレートと同じ書式のスプレッドシートを `{保存先}/{年度}年度/第{回}回/` に作成
- 写真添付（項目ごと／全体）、登録通知メール（固定の送信先1件）
- 入力内容はブラウザに自動保存。オフライン時の登録は保留し、オンライン復帰時に自動送信
- 過去データ（既存のExcel）の取込
- 管理DBのメニューから PDF 出力（未出力を一括／選択した行）。出力先は `{年度}年度/第{回}回/PDF/`、出力後「PDF出力」列に「済」

設計の詳細は [docs/設計提案.md](docs/設計提案.md) を参照。

## ファイル構成

| ファイル | 内容 |
|---|---|
| `src/Config.gs` | 設定（保存先フォルダID・シート名・スクリプトプロパティの読み込み） |
| `src/Code.gs` | ウェブアプリ（doGet）と画面から呼ばれるAPI |
| `src/Domain.gs` | 業務ルール（実施回判定・連続指摘・減点計算）。画面にも同じコードを埋め込んで使う |
| `src/Parser.gs` | テンプレート／過去レポートの解析 |
| `src/Repository.gs` | 管理DB（スプレッドシート）の読み書き |
| `src/ReportWriter.gs` | テンプレートの複製・書き込み、写真の保存 |
| `src/Notify.gs` | 登録通知メール |
| `src/Setup.gs` | 初期設定 `setup()`、テンプレート改版 `updateTemplate()` |
| `src/Import.gs` | 過去データ取込 `importPastReports()` |
| `src/Pdf.gs` | 管理DBのメニュー（`onDbOpen`）と PDF 出力 |
| `src/index.html` `css.html` `js.html` | 入力画面 |
| `dist/SVレポート登録.gs` | `src/*.gs` を1ファイルにまとめたもの（GASエディタへの貼り付け用。`npm run bundle` で生成） |
| `test/` | Node でのテスト（`npm test`） |

## 導入手順

画面操作つきの詳しい手順は **[docs/導入手順.md](docs/導入手順.md)** を参照。以下は概要。

1. **GASプロジェクトを作成**し、`dist/SVレポート登録.gs`（全 .gs を1つにまとめたもの）と `src/` の HTML 3ファイル・`appsscript.json` を配置する（[clasp](https://github.com/google/clasp) を使う場合は `.clasp.json.example` を `.clasp.json` にコピーして scriptId を設定し `clasp push`）。
   エディタで手作業で作る場合は `appsscript.json` も反映すること（「プロジェクトの設定」→「appsscript.json をエディタで表示する」）。
2. **テンプレートExcelをDriveにアップロード**し、ファイルIDを控える。
3. スクリプトエディタ「プロジェクトの設定」→「スクリプト プロパティ」に設定:

   | プロパティ | 値 |
   |---|---|
   | `TEMPLATE_XLS_FILE_ID` | 手順2のファイルID（必須） |
   | `NOTIFY_TO` | 登録通知の送信先メールアドレス |
   | `ROOT_FOLDER_ID` | 保存先フォルダID（省略時 `1fCaEEFJMTKgGPPINg7G5TuBNuohbwymo`） |

4. GASエディタ上部の関数選択プルダウンで **`setup`** を選び「▷ 実行」を押す（初期設定用のプログラムを1回だけ動かす。初回は権限の承認が必要）。保存先フォルダに `_システム` フォルダが作られ、次が自動で用意される。
   - `SVレポート_テンプレート`（Excelを変換したスプレッドシート）
   - `SVレポート_管理DB`（校舎マスタ・項目マスタ・登録履歴・明細・写真・取込ログ）
5. 管理DBの **項目マスタ「対象外業態」列** を確認・修正する（例: `アスモ`。複数はカンマ区切り）。
   「アスモは対象外」と書かれた項目は自動で設定済み。
6. **デプロイ** →「新しいデプロイ」→ 種類「ウェブアプリ」
   - 次のユーザーとして実行: **自分**（保存先フォルダへの権限はデプロイした人だけが持っていればよい）
   - アクセスできるユーザー: 同じ Google Workspace 組織の人だけなら **「（組織名）内の全員」**、
     個人の Gmail アカウントの担当者がいる場合は **「Google アカウントを持つ全員」**（`appsscript.json` の `webapp.access` を `ANYONE` に変更）
7. 発行されたURLを担当者に共有する。

### 過去データの取込

1. 過去のSVレポート（.xls / .xlsx / スプレッドシート）を1つのフォルダ（サブフォルダ可）にまとめる。
2. スクリプトプロパティ `IMPORT_FOLDER_ID` にそのフォルダIDを設定し、`importPastReports` を実行。
3. 結果は管理DBの「取込ログ」に記録される。6分の実行制限に近づくと中断するので、「未処理」が残る場合は再実行（処理済みのファイルは飛ばす）。

取込の仕様: E2（校舎ID）と G2（実施日）から実施回を判定し、L列（今回の減点）と K列（連続指摘回数）を項目文で照合して取り込む。同じ実施回が登録済みならスキップ。

### テンプレートの改版

新しいExcelをアップロードして `TEMPLATE_XLS_FILE_ID` を差し替え、`updateTemplate` を実行。新しい版の項目が項目マスタに追加され、現行版が切り替わる。
項目の追加・削除で No がずれた場合は、前回・前々回と正しく紐付くよう、新しい版の「項目キー」を旧版に合わせて修正する。

## 開発

```
npm run check   # 実装後のエラーチェック一式（1ファイル版の生成・構文・名前の重複・エントリポイント・全テスト）
npm test        # テストのみ
```

変更後は必ず `npm run check` を実行し「結果: すべてOK」を確認してからコミットする。

テストは、単体テストに加えて `test/gasenv.js`（SpreadsheetApp・DriveApp 等のモック）上で **貼り付け用の1ファイル版そのもの** を動かし、setup → 画面初期表示 → 登録 → 出力シートのセル内容 → 上書き → 過去データ取込 を通しで確認する。
