# SVレポート登録機能 設計書

対象テンプレート: `SVレポート_2026.10ver.xls`（シート「チェック項目」＋非表示シート「校舎一覧」）


## 0. 決定事項（2026-10-08 ヒアリング結果）

| 項目 | 決定内容 |
|---|---|
| 実施回 | 実施日から自動判定。第1回=1〜3月、第2回=4〜6月、第3回=7〜9月、第4回=10〜12月（年度＝暦年） |
| 連続指摘 | 前回と今回でレベルが違っても連続。5回目以降は×4。重要事項（-100）も倍率対象。年度またぎも連続。間の回が未実施でもリセットせず、直近の実施済みの回を参照 |
| N列・O列 | 前回・前々回の **倍率適用後** の減点 |
| 業態別の対象外項目 | あり → 項目マスタ「対象外業態」列で管理。加えて画面で項目ごとに「対象外」をチェック可能（併設校舎のみの項目など） |
| 現金・通帳残・TMS金額 | 入力必須。不一致の自動判定はしない |
| 過去データ | 取り込む（`importPastReports()`） |
| 出力形式 | 登録時は Google スプレッドシートのみ（PDF変換は別途追加予定） |
| 保存先 | `1fCaEEFJMTKgGPPINg7G5TuBNuohbwymo` の下に `{年度}年度/第{回}回/` |
| 利用者 | 複数の担当者が入力。閲覧のみの利用者はいない |
| 修正・取消・承認 | 考慮しない（同じ実施回を登録し直すと、確認のうえ上書き） |
| 端末・機能 | PCのみ。オフライン入力・写真添付・登録通知（固定の送信先1件）が必要 |
| マスタ管理・集計 | 当面は考慮しない |

## 2. 方式の推奨

**推奨: HTML（HtmlService）フロント ＋ GAS バックエンド（1つのGASウェブアプリ）**

| 観点 | Googleフォーム / スプレッドシート直接入力 | HTML＋GAS（推奨） |
|---|---|---|
| 前回・前々回の表示 | 不可（フォームは動的表示不可） | 校舎・回を選ぶと即表示 |
| 89項目×L/M/H、`*` の選択不可制御 | 困難 | 項目マスタから自動生成 |
| 連続指摘回数・減点の自動計算 | 数式頼み・壊れやすい | サーバ側で確定計算 |
| 現地でタブレット/スマホ入力 | 操作性が悪い | レスポンシブ対応可 |
| 下書き保存・再編集 | 困難 | 可能 |

構成はGAS単体（`doGet` で HTML を返し、`google.script.run` で通信）。別サーバ不要、Google Workspace のアカウントでアクセス制御できます。

## 3. 全体構成

```
[SV（ブラウザ/タブレット）]
      │  google.script.run
      ▼
[GAS ウェブアプリ]
  ├─ 管理用スプレッドシート（DB）
  │    ├─ 校舎マスタ / 項目マスタ / 担当者マスタ / 設定
  │    ├─ 登録履歴（1レポート1行）
  │    └─ 明細（1レポート×項目 1行）
  ├─ テンプレートスプレッドシート（Excelを変換したもの）
  └─ Googleドライブ 出力フォルダ
       └─ 年度 / 実施回 / 各校舎のレポート（スプレッドシート）
```

**重要な設計方針: 「前回・前々回」はDB（登録履歴・明細シート）から取得し、出力済みスプレッドシートを読みにいかない。**
出力ファイルは「帳票（成果物）」、DBが「正（Single Source of Truth）」。ファイル名変更・手修正・移動の影響を受けず、高速に取得できます。

## 4. 実施回の識別とキー設計

### 4-1. レポートキー
```
レポートID = {年度}-{実施回}-{校舎ID}     例: 2026-3-2351
```
- 同一校舎・同一年度・同一実施回は **1件のみ**（ユニーク）。
- 同じキーで再登録された場合は「上書き確認」→ 既存ファイルを更新し、履歴の版数(+1)と更新日時を記録。

### 4-2. 年度・実施回
- 実施日から自動判定（第1回=1〜3月 … 第4回=10〜12月、年度＝暦年）。
- 「前回」は年度をまたいで取得（2027年度第1回 の前回 = 2026年度第4回）。未実施の回は飛ばして直近の実施済みの回を参照。並び順は `(年度, 実施回)` で判定。

## 5. ファイル命名規則・フォルダ構成

### ファイル名
```
SVレポート_{年度}年度第{回}回_{校舎ID}_{校舎名}_{実施日yyyyMMdd}
例: SVレポート_2026年度第3回_2351_山口宇部校_20261008
```
- 先頭にID/年度/回を入れることでドライブ上でソート・検索しやすくする。
- 校舎名に使えない文字（`/` 等）は置換。
- ファイルIDは登録履歴に保存（以後の参照・上書きはIDで行う。名前検索に依存しない）。

### フォルダ構成（案）
```
SVレポート/                ← 指定フォルダ（ID を設定シートで管理）
  └─ 2026年度/
       ├─ 第1回/
       ├─ 第2回/
       ├─ 第3回/
       └─ 第4回/
```
別案: `年度/業態/実施回/` や `年度/校舎/`。閲覧者（AM、校舎）の見方に合わせて決定（**要確認**）。フォルダが無ければ自動作成します。

## 6. データ設計（管理用スプレッドシート）

### 校舎マスタ（Excelの「校舎一覧」を移行）
`校舎ID | 業態 | 地域 | 校舎正式名 | 経営 | 会社 | 開校日 | 備考 | 有効フラグ | 担当AM | 担当SV`
- 譲渡・閉校校舎は削除せず `有効フラグ=FALSE`（過去レポートの参照を壊さないため）。

### 項目マスタ（版管理あり）
`テンプレート版 | 項目キー | No | 区分 | 項目文 | 減点L | 減点M | 減点H | 出力行 | 並び順 | 対象業態`
- `*` は空欄（=選択不可）として保持。
- **項目キー**は版をまたいで不変のID（例: `KANBAN_01`）。項目文やNoが改版で変わっても、前回・前々回を正しく紐付けるため。
- `出力行` = テンプレート上の行番号（12〜106 等）。テンプレート改版時はここを更新するだけで出力位置が追従。

### 登録履歴（1レポート1行）
`レポートID | 年度 | 実施回 | 校舎ID | 校舎名 | 業態 | 実施日 | AM | SV | 現金 | 通帳残 | TMS金額 | 減点合計 | 点数 | テンプレート版 | ファイルID | ファイルURL | ステータス(下書き/確定) | 版数 | 登録者 | 登録日時 | 更新日時`

### 明細（1レポート×1項目 1行）
`レポートID | 校舎ID | 年度 | 実施回 | 項目キー | レベル(L/M/H/空) | 基本減点 | 連続指摘回数 | 適用減点 | 備考`
- 件数目安: 201校 × 4回 × 約92項目 ≒ 7.4万行/年。数年分なら問題ないが、重くなったら年度別シートに分割。

## 7. 処理フロー

### 入力画面表示
1. 校舎を選択（業態・地域で絞込み、ID直接入力も可）
2. 年度・実施回・実施日・AM・SV を入力（AM/SVは校舎マスタの担当を初期表示）
3. サーバから取得して表示:
   - 項目マスタ（現行版）
   - 前回・前々回の明細（レベル・減点・備考）＋各点数
   - 同じキーの登録が既にあれば、その内容（再編集）
4. 各項目行の表示例:
   ```
   No.12 ■教室長のネームホルダーの着用   [なし][L -1][M -3][H -5]
          前回: M(-3)  前々回: -   → 今回Mなら 連続2回目 ×2 = -6
          備考: [____________]
   ```
   - 前回指摘ありの項目はハイライト。合計点はリアルタイム表示。

### 登録ボタン押下
1. 入力チェック（必須項目、実施日の範囲、重複キー）
2. `LockService` で排他（同時登録による履歴破損防止）
3. 連続指摘回数・適用減点をサーバ側で再計算（画面の値を信用しない）
4. 登録履歴・明細へ書込み（同一キーは置換）
5. テンプレートを `makeCopy` → 指定フォルダへ配置 → セルへ一括書込み
   - ヘッダ（B2,C2,E2,G2,M3,M5）、L:M=今回、N=前回、O=前々回、K=連続回数、F:G=備考
   - 集計セル（L107:O108）はテンプレートの数式をそのまま利用
6. ファイルID/URLを履歴に保存し、画面に完了メッセージ＋リンク表示
7. （任意）AM・校舎へメール通知、PDF/xlsx の同時保存

## 8. 実装上の補足・残課題

### オフライン入力について
- GAS のウェブアプリは、**画面を開くこと自体はオンラインで行う必要がある**（オフラインで新しく開くことはできない）。
- 画面を開いた後に通信が切れても入力を続けられる。入力内容はブラウザ（IndexedDB）に自動保存され、ページを閉じても次回開いたときに復元される。
- オフライン中に「登録」すると保留され、オンラインに戻ったときに自動送信される（画面を開いている必要あり）。
- オフライン中は、その校舎の前回・前々回を一度も表示していなければ表示できない。ただし連続指摘・減点は登録時にサーバで再計算するので、登録結果は正しくなる。

### 写真
- ブラウザで長辺1600px・JPEGに縮小してから送信。
- 保存先: `{年度}年度/第{回}回/写真/{レポートID}_{校舎名}/`。レポートの「写真」シートに項目とリンクを一覧で出力。

### 対象外の扱い
- 業態で対象外の項目、または画面で「対象外」にした項目は減点 0、備考に「対象外」と出力。
- 前回が対象外だった項目は「前回減点なし」と同じ扱い（連続回数はリセット）。

### 残課題（ご確認ください）
1. 業態ごとの対象外項目の一覧（現状は「アスモは対象外」と書かれた No.59 だけを自動設定）
2. K列（連続指摘回数）は、減点がある項目すべてに回数（1回目なら1）を出力している。2回目以降だけ表示したい場合は変更する
3. 点数がマイナスになる場合もそのまま出力している（下限なし）
4. 過去にさかのぼって登録・修正した場合、それより後の回の連続回数は自動では再計算しない（画面に警告を表示）
5. 過去データの取込: 古い版のテンプレートは列の配置（K/L列、E2/G2）が同じことを前提にしている。違う版がある場合は見本を共有してほしい
